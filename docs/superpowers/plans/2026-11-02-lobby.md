# Lobby Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players choose a name, then create or join lobbies (from a list or by room code); one server runs one game per lobby, with a leader, spectators and promotion.

**Architecture:** The protocol gains a string type and lobby messages (13–22). The server splits into `Game` (one engine world), `Lobby` (one lobby's rules, no networking), `Lobbies` (all lobbies by code) and `Server` (clients, packets, tick). Lobby state is re-sent like snapshots; the client re-sends each request until the state reflects it. The client becomes one window switching screens built on a small widget layer, so menu art can replace the placeholder drawing later.

**Tech Stack:** C++20, CMake 3.25 + Ninja presets, vcpkg (SFML 2.6, Asio), assert-based ctest tests, Python 3 standard library for the black-box test.

**Spec:** `docs/superpowers/specs/2026-11-02-lobby-design.md` — read it first; section numbers below (§) refer to it.

## Global Constraints

- Work on branch `Lobby` (from `origin/login_page`). Do not commit to `login_page`. Do not push.
- Build and test **inside the `ntype-dev` container** (the host lacks OpenGL headers). Every "Run" below means:
  `podman start ntype-dev >/dev/null; podman exec -w "$PWD" ntype-dev bash -c 'export VCPKG_ROOT=$PWD/vcpkg && cmake --preset linux-release >/dev/null && cmake --build --preset linux-release && <COMMAND>'`
  with binaries in `build/client-linux-release/bin/`.
- Compiler flags stay `-Wall -Wextra -Wpedantic -Wconversion` (MSVC `/W4 /permissive- /utf-8`): the build must have **no warnings** in new code. Code must also build on Windows (no POSIX-only calls).
- Style: protocol code uses camelCase (`makeLobbyJoin`, `yourSlot`) and the EPITECH header; server/client code uses snake_case members with trailing `_`, namespaces `ntype::server` / `ntype::client`, 4-space indent, `.clang-format` at the root.
- Tests are `assert` programs compiled with `-UNDEBUG`, registered with `add_test`, printing one `PASS`-style line on success (like `protocol_test`).
- Limits (§2): code = 4 chars from `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`; player name 1–16; lobby name 1–24; printable ASCII 32–126; 4 members per lobby; 32 lobbies; 128 clients; `kMapCount = 3`; default lobby name `"<player>'s lobby"`.
- Timings: tick 60 Hz; `LobbyState` every 6 ticks; client list request every 1 s; request re-send every 250 ms, give up after 3 s; connect retry 500 ms, "No server answered" after 3 s; silence timeout 5 s.
- Error texts (exact): `No server answered on <host>:<port>`, `Server did not respond`, `Connection lost - reconnecting`, `No lobby with this code`, `This lobby is full`, `The server has too many lobbies`. Spectator banner: `Spectating — you'll join at the next level`.

## Review Focus

1. **Lost `LobbyLeave`** — the client thinks it left, the server still has it in the lobby, so the next Create returns the old lobby. Expected: leaving is retried until confirmed and self-heals. (Plan refinement of §4.3: the server answers every `LobbyLeave` with a `LobbyList`, which is the confirmation; a client that is browsing and still receives `LobbyState` re-sends `LobbyLeave`.) Tests in Task 4 (smoke) and Task 5.
2. **Leader leaves mid-game and only spectators remain** — expected: the game ends, the lobby is waiting, the remaining member is leader and a player. Test in Task 3.
3. **A member sends `LobbyJoin`/`LobbyCreate` for another lobby** — expected: stays in its lobby and gets its current state. Test in Task 4 (smoke).
4. **Connection lost while in a lobby** — expected: the client returns to Connecting with `Connection lost - reconnecting`, and after reconnecting is browsing, not in a stale lobby. Test in Task 5.
5. **A spectator holds keys** — expected: nothing moves and no ship appears for it until promotion. Test in Task 4 (smoke).

```cpp
namespace ntype::server {
using ClientId = std::uint32_t;

struct Member {
    ClientId client = 0;
    std::string name;
    std::uint8_t slot = 0;               // 1 to 4, lowest free on join
    protocol::MemberRole role = protocol::MemberRole::Player;
};

// One lobby's rules. No networking: the Server feeds it requests and sends what it builds.
class Lobby {
public:
    Lobby(std::string code, std::string name, std::uint8_t map);  // map >= kMapCount becomes 0
    const std::string& code() const;
    protocol::LobbyPhase phase() const;
    const std::vector<Member>& members() const;   // arrival order; front() is the leader
    bool empty() const;
    bool has(ClientId client) const;
    bool join(ClientId client, std::string name); // false when 4 members; true without change if already in
    void leave(ClientId client);                  // ends the game if no player remains while playing
    bool rename(ClientId by, std::string name);   // leader + waiting only
    bool set_map(ClientId by, std::uint8_t map);  // leader + waiting + map < kMapCount
    bool start(ClientId by);                      // leader + waiting; everyone becomes a player with a ship
    void on_level_start();                        // spectators become players with a ship
    void end_game();                              // back to waiting, game destroyed, everyone a player
    void set_input(ClientId client, std::uint8_t keys);  // players of a running game only
    void step(float dt);                          // no-op while waiting
    std::vector<protocol::Entity> snapshot() const;      // empty while waiting
    protocol::LobbyInfo info() const;
    protocol::LobbyState state_for(ClientId client) const;  // yourSlot = that member's slot
};

class Lobbies {
public:
    explicit Lobbies(std::uint32_t seed = std::random_device{}());
    Lobby* create(std::string name, std::uint8_t map);  // nullptr at kMaxLobbies; fresh unused random code
    Lobby* find(const std::string& code);
    Lobby* lobby_of(ClientId client);
    void remove_empty();
    std::vector<protocol::LobbyInfo> list() const;      // ordered by code
    std::map<std::string, Lobby>& all();
};
}
```

Request handling (§4.3, plus the Review Focus 1 refinement):

| Message | Server reply |
|---|---|
| `ConnectRequest(name)` | known endpoint → `ConnectAccept` again; 128 clients → `ConnectRefuse ServerFull`; else add client, `ConnectAccept` |
| `LobbyListRequest` | `LobbyList(lobbies_.list())` |
| `LobbyCreate(name, map)` | in a lobby → that `LobbyState`; `create` null → `LobbyRefuse TooManyLobbies`; else create, join, `LobbyState` |
| `LobbyJoin(code)` | in a lobby → that `LobbyState`; unknown → `NotFound`; full → `Full`; else join, `LobbyState` |
| `LobbyLeave` | leave if in one, `remove_empty()`, then **always** reply `LobbyList` |
| `LobbyRename` / `LobbySetMap` / `LobbyStart` | apply via `Lobby`; reply `LobbyState` (changed or not) |
| `Input(keys)` | store; `lobby->set_input` |
| `Disconnect` / 5 s timeout | leave lobby, `remove_empty()`, erase client; send `ClientLeft(slot)` to that lobby's remaining members if it was playing |
| any other from unknown endpoint | ignored |

Tick (§4.4): poll datagrams → run console commands → drop timed out → for each playing lobby `step(kDt)` and send `makeWorldSnapshot(snapshot())` to its members → if `tick_ % 6 == 0` send each member `makeLobbyState(state_for(member))`.

Console commands: `level <CODE>` → `on_level_start()`, `gameover <CODE>` → `end_game()`; code is upper-cased; print `[server] level started in K7QX`, `[server] game over in K7QX` or `[server] unknown command: ...`.
